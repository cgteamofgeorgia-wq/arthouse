# BuildHub — ბექენდის დანერგვის სახელმძღვანელო

ეს ფაილი ხსნის, როგორ უკავშირდება ერთმანეთს ტექნიკური დავალების მოთხოვნები
და კოდში არსებული რეალიზაცია. ფაილები ამ საქაღალდეში იდება პროექტის
ფესვში იმავე ბილიკებით.

## 1. სქემის გაშვება

```
supabase/migrations/0001_init.sql   → ცხრილები, ტიპები, ტრიგერები
supabase/migrations/0002_rls.sql    → Row Level Security პოლისები
supabase/seed.sql                   → ენები, პაკეტები, რეკლამის პოზიციები, კატეგორიები
```

## 2. გარემოს ცვლადები

`.env.example`-ის საფუძველზე შეავსეთ: Supabase-ის გასაღებები, Meilisearch,
გადახდის პროვაიდერების საიდუმლოები (`PAYMENT_SECRET_PAYZE`, `PAYMENT_SECRET_TBC`,
`PAYMENT_SECRET_BOG`, `PAYMENT_SECRET_STRIPE`), Resend/SendGrid, SMS, `CRON_SECRET`,
`CODE_PEPPER`.

## 3. უსაფრთხოების ხაზინა — სად რა მოწმდება

| წესი (TD) | სად ცხოვრობს |
| --- | --- |
| განცხადება არ ქვეყნდება callback-ით, მხოლოდ webhook-ით | `payments/webhook/[provider]/route.ts` + ტრიგერი `payments_activate` |
| webhook-ის კრიპტოგრაფიული შემოწმება | `lib/payments/registry.ts` → `verifyWebhook` (HMAC-SHA256, დროით უსაფრთხო შედარება) |
| idempotency — ორმაგი გადახდა | `payments` უნიკალურობა `(provider, idempotency_key)` + `payment_events` |
| სერთიფიკატს ადასტურებს მხოლოდ ადმინი | RLS პოლისი `certs_admin_update` + `requireAdmin()` |
| ავტომატური დადასტურება დაუშვებელია | insert ყოველთვის `status='submitted'`-ით |
| ვერიფიკაციის ყველა ქმედება აუდიტში | `writeAudit()` ყოველ ადმინის ოპერაციაზე |
| ბარათის მონაცემები არ ინახება | პროვაიდერის redirect + ტოკენი; ბაზაში მხოლოდ `tx_id` |
| rate limiting | `rateLimit()` — რეგისტრაცია, შესვლა, ჩატი, ატვირთვა |
| 2FA ადმინისთვის | `auth/login` — TOTP კოდის გარეშე სესია არ გაიცემა |
| GDPR — ანგარიშის წაშლა | soft delete + `deleted_at`, კასკადური წაშლა მოთხოვნით |

## 4. ფონური ამოცანები (Vercel Cron)

| მარშრუტი | განრიგი | რას აკეთებს |
| --- | --- | --- |
| `/api/cron/maintenance` | ყოველდღე 03:00 | ვადაგასული განცხადებები, სერთიფიკატების ვადა, 30-დღიანი შეხსენება |
| `/api/cron/payment-reminders` | ყოველდღე 10:00 | წარუმატებელი გადახდის შეხსენება მე-2 და მე-7 დღეს |
| `/api/cron/fx-rates` | ყოველდღე 09:00 | NBG-ის კურსების ჩამოტვირთვა ოთხ ვალუტაში |

ყველა cron მარშრუტი მოითხოვს `Authorization: Bearer $CRON_SECRET`.

## 5. Realtime ჩატი

კლიენტი უსმენს არხს `chat:{conversationId}`. RLS უზრუნველყოფს, რომ მხოლოდ
მონაწილეებმა მიიღონ ჩანაწერები. „წერს ახლა“ და ონლაინ სტატუსი გადადის
broadcast-ით იმავე არხზე; წაკითხვის სტატუსი ინახება `messages.read_at`-ში.

## 6. რა არის განზრახ გამოტოვებული

- **ფრონტენდი** — TD ამბობს, რომ დემო ინტერფეისი უკვე აწყობილია; აქ მხოლოდ ბექენდია.
- **PDF-ის რენდერი** ინვოისისთვის რეალურ პროდაქშენში `@react-pdf/renderer`-ით
  უნდა გაკეთდეს; აქ HTML-შაბლონია, რომელიც Storage-ში ინახება.
- **Meilisearch-ის ინსტანსი** — `ensureIndex()` ერთხელ უნდა გაეშვას deploy-ისას;
  ქართული მორფოლოგიისთვის საჭიროა დამატებითი synonym-ფაილი (TD 4.5).
- **ვირუსული სკანირება** — ClamAV ან VirusTotal hook ატვირთვის დასრულებისას.
